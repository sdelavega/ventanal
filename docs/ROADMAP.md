# Ventanal roadmap

Owner wishes recorded 2026-11-16; order and approach decided by the maintainers.

## v1 — first public release (in progress)
- Web settings page: Status, Settings (done), Art, Calibration (in progress), then transport security: HTTPS with a pinned certificate plus signed manifest, frames and reports whenever a password is set.
- **Pluggable art sources.** New sources (Rijksmuseum keyless, National Gallery of Art, Paris Musées, SMK, Wikimedia Commons off by default) are built on a source plugin interface: one module per source declaring its search/fetch, rights filter (explicit public domain / CC0 only), credentials it needs (shown on the Settings page), rate limits and attribution. Plain REST APIs, IIIF, SPARQL and bulk open-data dumps all fit the same interface, so later sources are additive.
- README, 48-hour battery soak, clean public history.

## v1.1 — personal photos and host hardening
- **Run the host in a container.** Package the current Python service as a Docker image (non-root user, read-only root filesystem, only the state and config volumes writable, no extra capabilities). This brings most of the isolation benefit now, before any rewrite.
- **Personal libraries as sources** (built on the plugin interface): Dropbox, Google Drive and OneDrive through their official OAuth APIs — the user picks a folder; tokens stored encrypted at rest; requires the v1 transport security to be enabled. iCloud Photos has no official public API for photo libraries: support public Shared Albums by link (best effort, may break if Apple changes it) and document the limitation. Personal photos are treated as confidential: never logged, never cached longer than needed, excluded from any telemetry.

- **Setup wizard** (owner request 2026-11-16) — a desktop app for Windows 10+, macOS 26+ and Linux 6.12+, alongside the README. Built with Tauri (Rust backend, web UI reusing the LCARS styles), which is where Tauri fits in this project. Steps: detect the board on USB (and guide installing the CH340 driver where the OS needs it), flash a **prebuilt** firmware image (no Arduino toolchain on the user's machine), and **provision settings over serial into the board's NVS** — Wi-Fi, host URL, rotation, and the pinned certificate fingerprint and device key from the transport-security pairing — so `config.h` stops being something users edit (it stays as a developer default). Then set up the host: either this computer (Docker Desktop / Docker Engine) or a remote Linux box such as a Raspberry Pi over SSH, deploying the v1.1 container image; finally open the web settings page to choose the password. Signed and notarised builds per platform, published with each GitHub release: macOS with the owner's Apple Developer ID + notarisation; Windows via Microsoft's Azure Trusted Signing (low-cost, needs identity validation) when v1.1 is built — until then Windows builds are unsigned and the README explains the SmartScreen prompt. Requires firmware support for NVS provisioning and published firmware binaries in CI.

## v2 — Rust
- **Host in Rust**, in the same container model (an async HTTP server such as axum; same board protocol and web UI). Tauri is a desktop-app framework and doesn't fit a headless Raspberry Pi; if a desktop companion app is wanted later (for setup or calibration on a laptop), that is where Tauri belongs.
- **Firmware in Rust** (esp-rs on the ESP32-S3, std/esp-idf): port what we can of Soldered's Inkplate SDK (panel controller over SPI, IO expander, battery measurement, RTC), recreate the rest, and keep the documented stall handling. Heavily commented so it can serve as a template for other ESP32 Rust e-paper projects.
- **Board abstraction** in the Rust firmware and host: one trait/profile per display (resolution, palette, refresh behaviour, buttons, battery), which is where support for other ESP32 e-paper boards lands (best effort, community-tested).
- **Touch input** on displays that have it (e.g. touch-enabled Inkplate models), designed into the board abstraction: tap zones for next/previous art and screen switching, mirroring the button actions.
